# Changelog

## Unreleased — 0.0.0 pre-alpha

Phase 0/1 walking skeleton implemented and fixture-verified: private queue and task validation, foreground controller, provisional external OpenCode adapter, worktree verification, authenticated read-only dashboard, stateless CLI/MCP and Claude Code plugin scaffold. Fixture validation is separate from pending real endpoint qualification, live plugin sessions and release onboarding. No 0.1.0 release is claimed.

Crash recovery preserves uncertain execution and pauses dispatch until explicit owner reconciliation. Attempt finalization and service ownership are transactional. Scope/protected glob patterns are positive-only; dashboard sessions use a private path to avoid cross-port cookie exposure. Real endpoint qualification remains pending.

Phase 2 adds versioned class policy, read-only local reviews, cumulative bounded repairs, owner-session frontier claims/reviews, manual availability/reset settings and private launchd/systemd user services. Strict JSON/SHA gates, transactional review evidence and worker/reviewer interruption fences preserve deterministic acceptance. The service makes no automatic paid calls. Real model qualification and live session/marketplace onboarding remain separate gates.

Phase 3 adds a transactional evidence outbox with acknowledged-prefix JSONL replay, scorecards with measurement coverage, atomic owner decisions and sampled owner-session audits. Public export requires repository publication opt-in and verified public GitHub visibility, with a closed anonymous projection and historical profile bindings. Seven fixed local qualification workloads, durable interrupted-job fences, community schemas and isolated package/CLI/MCP onboarding checks are implemented. Fixture tests establish pipeline behavior; actual qualification, owner acceptance and release evidence remain separately recorded.

Qualification workload v2 states the exact discovery glob requirement that v1's grader already enforced. Historical v1 assets/results remain intact and inspectable; verification predicates and budgets are unchanged.

Qualification workload v3 distinguishes complete explicit read pages from lost evidence using exact structured and rendered page boundaries. Byte caps, line truncation, ambiguous evidence and incomplete full-ledger context still fail. V1/v2 assets, observations and outcomes are preserved; no historical regrading or model qualification is inferred.

Actual harness integration revealed concurrent automatic title generation and custom-model sampling settings being ignored. The adapter now disables auxiliary/subagent/automatic-compaction inference, selects primaries explicitly and enables temperature support with a zero default. Optional installed-binary wire smoke verifies actual request count, sampling and worker/reviewer permissions without provider inference. Qualification runs/results are also inspectable in the read-only dashboard.

Phase 3 onboarding adds authenticated `doctor` operational diagnostics without inference or policy changes, a bundled versioned Apache-2.0 pilot creator with protected checks and separate private task files, and static plugin footprint measurement without invented token counts. Local pilot tasks require default review; risky work holds for an authorized frontier session. Creation does not bank tasks, grant qualifications, accept results or publish evidence.

Phase 3 evaluation adds saved qualification requirement checklists through `qualify explain`, bearer-authenticated diagnostics and the read-only dashboard. Checklists share existing observer predicates and require exact replay parity; history, workload revisions and grading gates stay unchanged. Scorecards and permission-gated exports add closed declared task measurements with unknowns and small-sample owner-decision denominators, without quality or causal claims.
