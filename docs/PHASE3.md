## Architecture and integrity

SQLite v4 is authoritative. Task mutations, decision/audit records and settings changes append immutable evidence snapshots in the SAME transaction. A private JSONL writer drains ordered snapshots after commit, fsyncs before acknowledgement, verifies existing prefix against SQLite, recovers an incomplete final line only, and handles complete-write-before-ack without duplicates. Never overwrite complete evidence. On failure preserve pending SQLite rows, expose safe delivery health and retry; do not lose an otherwise committed task decision. Legacy backfill is explicitly legacy-snapshot and never invents historical frontier availability.

Store ready_at/completed_while_frontier_off at readiness transition from observed settings; old ready records have null/unknown. Capture ordinary versus qualification task provenance, effective policy version/snapshot at admission, role-tagged usage, and immutable owner decision minutes (optional). Missing usage stays missing. Report task decisions separately from worker/check success. Qualification tasks are excluded from ordinary work scorecards by default. Audit requests are selected once at owner acceptance for checks-only/local tier: configurable audit_rate 0..1, default .30, random Bernoulli selection. Selected audits denied by repo policy remain visibly pending; never silently remove them from denominators. Audits do not rewrite acceptance or task state and do not launch a model.

Audit submission is exact-SHA strict ReviewReport and reported/owner-attested metadata. Gate packet/submit on frontier available + current repository frontier-ok after awaited preparation. Review accepted immutable commit objects in detached/read-only context; do not require a result branch still to exist after a normal merge. Validate object still exists and original independently passed checks; do not reuse edited worker residue. One immutable audit per accepted result, reject replay/stale SHA. A needs-repair/reject audit is a miss; accept with warnings is not a blocking miss. Show sample counts and pending audits; no percentage with denominator <20. Frontier planning usage is optional explicit owner entry, never inferred; costs/tokens remain reported, coverage counts expose missing values, no savings claim without a baseline.

Sanitized export uses a closed projection, NEVER raw specs/prompts/check commands/logs/errors/findings, paths, endpoint IDs/URLs, private names, original task/profile IDs, owner notes or timestamps. Repository publication permission is separate from inference data_policy and defaults absent/denied: publication:{public_url:'https://github.com/OWNER/REPO'}. Verify public_url anonymously against fixed api.github.com repos endpoint, no credential discovery/redirects; private/404/rate-limit/offline all fail closed. Export only matching registered repo, never the rest of queue. Stable within-export synthetic task/profile labels; include class, tier, state, numeric timing/check/usage/decision/audit outcomes and exact public profile metadata from an explicit reviewed manifest. Manifest optional: absent metadata remains unknown and reproducible=false. Accepted ordinary outcomes, including failures/holds/abandonment, remain represented. Strong known secret/URL/IP/path checks for all free-text manifest identifiers; exact SHA and semver fields only where feasible. Never auto-publish export.

### Crash-safety addendum before qualification integration

Qualification invokes real subprocesses and therefore must persist execution before launch, not rely on the controller's in-memory slot. QualificationJobRecord frozen in contracts: id/profileId/root/status running|completed|failed|uncertain/start/end/resultPath/reason/reconciledAt. Store v4 also creates qualification_jobs. Methods createQualificationJob({id,profileId,root}), getQualificationJob(id), listQualificationJobs(), finishQualificationJob(id,status completed|failed|uncertain,resultPath?:string,reason?:string), reconcileQualificationJob(id). Creation shares all attempt/review/job and uncertainty fences; recovery marks running jobs uncertain. Reconciliation records one immutable owner-stopped attestation timestamp without rewriting uncertain outcome. Task and job fences both affect all inference. Each job mutation emits private outbox evidence. Root writes/fsyncs result before finalizing; unknown run exceptions retain uncertain fence, known returned failures are completed observational results. GET /api/v1/qualifications + POST /api/v1/qualifications/:id/reconcile {worker_stopped:true}; CLI qualify list/reconcile JOB-ID --worker-stopped. All operations through service only.


Historical reviewer reproducibility: v4 additionally stores nullable immutable review modelArtifact/harness/harnessVersion snapshots from actual local dispatch. Existing v3 reviews remain null/unknown; exporters cannot certify them using later current profile metadata. NewReview accepts optional snapshot fields; ReviewRecord returns optional nullable fields for compatibility. Root owns this additive contract/migration fix after independent review.


Long-running qualification addendum: optional POST /api/v1/qualify background:true returns 202 {job} only after durable admission, while service-owned execution retains the exclusive slot. Pre-admission failures retain normal error status and create no job. Post-admission errors are recorded as uncertain, consumed by the service and inspectable after client disconnect. GET /api/v1/qualifications/:id returns {job,result|null} from a bounded, private managed result file. CLI qualification uses background admission, plus qualify show JOB-ID; the synchronous HTTP form remains compatible for existing callers. Service shutdown aborts and awaits both the controller and background job promises before closing SQLite. This avoids transport headers timeouts being mistaken for a stopped worker.


Actual-harness budget addendum: OpenCode v1.19.0 automatically forks title inference and custom provider model temperature capability defaults false. The adapter disables title/summary/compaction/subagents, automatic compaction/pruning and batch delegation; selects explicit worker/reviewer primaries; declares model temperature support; defaults sampling to zero and records primary/temperature privately. Worker task/skill tools are denied. The output-token limit is preserved; context overflow fails rather than creating hidden inference. Actual installed-binary loopback wire smoke must establish one primary completion, transmitted temperature and tool permissions; serialized fixture assertions alone do not establish this. Interrupted exploratory runs retain private evidence/uncertainty and cannot qualify profiles.

### Read pagination correction contract

Actual v2 evidence shows OpenCode 1.19.0 sets read metadata `truncated` for a fully delivered requested page whenever the file has further lines. This differs from lost transcript data. V3 preserves v1/v2 assets/outcomes, copies v2 workload instructions and protected assets, and changes only this evidence interpretation. Strict result validators accept suite versions 1, 2 or 3; default manifest/prompt version is 3. Result format remains 1.

For v3 only, accept a completed read's pagination flag when a positive explicit limit, effective offset, matching structured display/path/counts and complete rendered page/footer establish delivery of exactly the requested page. Support file and directory pages. Any ambiguity, byte-cap or line-truncation marker, timeout, non-read truncation, malformed/duplicate/truncated outer stream still fails closed. Multi-round retains its full-context read/search, minimum observed bytes, edit/check and round requirements. V3 requires positive full-ledger proof: matching path/display, lines 1–256, intact text and exact end-of-file rendering. Partial pages and offset tails count as observed activity but cannot satisfy this gate. Expose an optional suite version to observeToolEvidence (default 3) so v1/v2 replay retains original behavior; runQualification passes its actual suite version. Never regrade stored reports or combine passing cases across runs.

Execution agent owns qualification module/result schema/tests and new eval/workload-v3 assets; root owns service parser, integration fixtures, package smoke and docs. Verify real recorded pagination with sanitized fixtures/replay and negative cap/timeout/shape cases, legacy parsing and exact retained asset bytes.
