## Frozen boundaries

Read-only Git inspections ignore global/system config and fail closed for bare repositories or failed outside-Git probes. `validateConfig` calls this planner then retains existing data-directory preparation; loadConfig retains existing behavior. Profile `qualified_classes:[]` becomes valid in runtime and JSON schema. Existing class eligibility/admission/dispatch/review checks still deny absent grants; no defaults or migrations invent permissions. Example config starts with an empty list.

`initializeConfig({inputPath:string,root:string}):Promise<InitReceipt>` in new init.ts. Read one bounded strict JSON input from an owner-only single-link regular file outside Git, with an immediate owner-private canonical parent directory, nofollow/nonblocking/stable identities, fatal UTF-8 and no raw errors/content reflected. Bound 256 KiB; reject duplicate/unknown fields and malformed input. Input shape `{version:1,repo:string,endpoint:{url:string,api_key_env?:string,api_key_file?:string},model:string,model_artifact:string,harness_version:string,port?:number}`. Reuse existing config validation for exact nonempty model/artifact/version, URL and explicit mutually exclusive credential references. No secret discovery or credential-value reading. All values are explicit operator inputs, not inferred qualifications.

Create a NEW owner-private root outside every normal/bare Git repository, with an existing real canonical parent owned by the user and not group/world writable. Reject existing root/file/link before writes. Validate all input and planned config before creating root; use planConfig with prospective root/data. Verify parent identity before creation and all managed directory identities/permissions between writes. No chmod of existing paths, recursive mkdir, replacement or deletion. Create exclusive root0700, data0700 and config.yaml0600 (YAML serialization, no arbitrary supplied config fields). Fixed config: version1, one registered canonical repo with local-only policy, one local endpoint/profile both id local, provided model/artifact/harness version, qualified_classes[], default_profile local, allow_checks_onlyfalse, port supplied/default7433, poll interval5000, audit_rate.30, data_dir root/data. Default policy is validated but can remain omitted in serialized starter. No publication grant, hosted/frontier enrollment or explicit policy override.

Require nofollow/exclusive config open, fsync file/root directory, stable file/parent identities and safe failure preservation. If creation fails, preserve only the newly created partial root for owner inspection; never clean up ambiguous foreign substitutions or alter existing content. Only local bounded isolated Git inspections are allowed (minimal environment, no global configs/hooks/network); no harness/catalog/network/service/queue operations. Input and prospective destination must stay disjoint; no repository/config/evidence writes outside the selected new root.

Receipt `{version:1,configPath:string,dataDir:string,profileId:'local',qualifiedClasses:[]}` contains only generated paths/fixed fields, no endpoint/model/artifact/credential values. Root integrates standalone `spillway init --from INPUT --directory NEW_ROOT`, available without a service. Reject global --config/--data-dir overrides for this command to prevent ambiguous destination; input and root are explicit. Return JSON receipt and safe fixed failures; arbitrary malformed input/error text stays private. Existing configs/services are never modified. Use printed config with existing global --config on later commands. README/setup show a private copied template and deliberate class grants only after real evidence; tools never add them automatically.
