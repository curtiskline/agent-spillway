## Frozen contracts

`task-features.ts` exports `TaskSpecFeatures` and `deriveTaskSpecFeatures(spec:TaskSpec):TaskSpecFeatures|null`. Features are `{bodyBytes,scopePatterns,contextFiles,checkCommands,hasNoChecksJustification}`: nonnegative safe integer UTF-8 byte/count measurements and one boolean. Validate measured fields defensively; malformed legacy data returns null. Scope patterns count declarations, not changed files; checks and context counts do not establish quality. No raw text, paths, commands or identifiers enter features.

Add `Scorecard.taskSpecs` `{version:1,measures:'declared-only',byCheckPlan,byContext,byScopePatterns,byBodySize}`. Each fixed bucket contains existing `OutcomeCounts` plus `acceptance:Ratio` using owner-decided denominator and null percentage below 20. Buckets: check plan `checks|justified-no-checks|missing-checks|unknown`; context `listed|empty|unknown`; scope `one-pattern|multiple-patterns|empty|unknown`; body `up-to-1k|1k-to-4k|over-4k|unknown` with inclusive 1024/4096 byte boundaries. All ordinary tasks appear once in every dimension; qualification stays excluded. Add `SanitizedExport.tasks[].taskSpec:TaskSpecFeatures|null`, retaining all publication gates. Measurements cannot infer task quality, causal effects or eligibility.

Refactor the current private qualification predicates into shared checklist predicates without changing results. `explainToolEvidence(text,capability,worktree?,suiteVersion=3)` returns `{evidence:ToolEvidence,checks:QualificationRequirementCheck[]}`; `observeToolEvidence` continues returning byte-for-byte equivalent object values for every supported revision. Checks `{id,met,message}` have closed IDs and fixed messages. Common IDs `complete-transcript|final-stop`; capability IDs `inventory-read|discovery-glob|ledger-search|scoped-edit|command-success|tool-failure|tool-recovery|repair-sequence|full-context|acceptance-check|assistant-rounds|successful-tool-rounds`. Requirements remain exact commands, exit codes, ordering, full ledger and existing version-specific filtering. No second grader or explanation inferred from stripped observations.

`qualification-diagnostics.ts` exports `buildQualificationDiagnostics({job,result,dataDir}):Promise<QualificationDiagnostics>`, strict `qualificationDiagnosticsSchema` and `formatQualificationDiagnostics(report):string`. Report `{version:1,jobId,suiteVersion:1|2|3|null,cases:[{capability,status:'available'|'not-recorded'|'unavailable'|'mismatch',checks:QualificationRequirementCheck[]}]}` with all seven capabilities in canonical order. A null suite version requires all rows to be not-recorded. No raw log, paths, arbitrary errors, model/config identifiers or metadata. Missing result/case/log path is not-recorded; unsafe/missing/unreadable transcript is unavailable; replay unequal to stored observations is mismatch with empty checks. Only exact replay parity exposes a checklist. Even invalid-transcript parity may expose failed common checks. Never mutate stored reports or turn a checklist into qualification.

Read only exact managed `dataDir/qualifications/JOB/artifacts/CAP/worker.log`; require stored job root/log path/worktree to equal derived managed paths. Worktree is `root/runtime/CAP/worktrees/worker-INDEX-qual-CAP` (one-based canonical capability index). Private canonical owner-only directories; owner-only single-link regular files; no-follow/nonblocking open; bounded 16 MiB + 128 bytes matching existing log bound; verify identities, metadata and size before/after reads and directories again. Reject substitution/escape without exposing file contents. No subprocess, network, model, writes or reconciliation.

Root adds `Controller.qualificationDiagnostics(id)`, bearer-only `GET /api/v1/qualifications/:id/diagnostics` including private dashboard API aliases, and `qualify explain JOB-ID [--json]`. Validate CLI arguments before HTTP and strict closed response; inspection exits 0 even for unmet requirements, transport/invalid responses fail. Bounded client timeout 30 seconds. Authenticated dashboard can render the safe checklist through the controller and explain unavailable/mismatch states. Existing MCP tools and qualification result format stay unchanged. Dashboard/report measurement tables state their declared-only limits.
