## Architecture and contracts

`doctor.ts` builds a diagnostic report inside the service from its validated configuration, adapter and operational snapshot. `GET /api/v1/doctor` is authenticated bearer-only; the CLI remains a thin client. The operation performs bounded harness version inspection and local catalog GETs, never model inference, installation, queue admission, reconciliation, policy changes or credential discovery. Hosted/frontier destinations are skipped. Configuration validation remains the existing startup requirement. An unavailable service produces a closed diagnostic failure with setup guidance, not raw exception/config text. Warnings do not certify capability.

`DoctorReport`: `{version:1, serviceVersion:string, ok:boolean, checks:DoctorCheck[]}`. `DoctorCheck`: `{id:'service'|'execution'|'recovery'|'evidence'|'harness'|'catalog'|'qualification', status:'pass'|'warning'|'fail', message:string, profileId?:string}`. Messages are fixed actionable text; no raw errors, endpoint URLs, model IDs, paths, tokens or returned version text. `ok` means no fail checks, not qualified or idle. Active execution and pending evidence are warnings; unresolved execution or evidence errors fail. Exact adapter/non-frontier worker-profile harness-version mismatch or missing configured local catalog model fail. Nonlocal catalogs, an unused harness for frontier-only profiles and operator-asserted task-class qualification are warnings. Aggregate checks omit optional profile IDs to avoid reflecting arbitrary config identifiers. No task classes or historical results change.

Export `buildDoctorReport({config,adapter,busy,uncertain,evidence}):Promise<DoctorReport>` and `formatDoctorReport(report):string`. Module owns its types and tests. Root integrates `Controller.doctor(evidence)` and server/CLI. `spillway doctor [--json]` returns 0 for no fail checks and 1 otherwise; invalid arguments fail before HTTP. Client timeout 30 seconds for this bounded operation. Existing five MCP tools remain unchanged.

`pilot.ts` materializes a bundled Apache-2.0 task set into a NEW owner-private root outside any Git checkout. The parent must already exist; reject existing root/file/symlink or roots within Git before writes. Do not replace or delete existing content. Create a fresh repo under `ROOT/repo`, three task Markdown files under `ROOT/tasks`, and private `ROOT/manifest.json`. No config, state, tasks or evidence are written into a target/existing repo. Only the intentional new public fixture repository contains code/checks/license. No networking, inference, installation, task banking, credentials or owner decisions occur.

Export `createPilot(root:string):Promise<PilotManifest>`. Manifest `{version:1,suiteVersion:1,license:'Apache-2.0',suiteHash:string,repo:string,baseSha:string,tasks:Array<{id:string,path:string,class:'mechanical'|'small-fix'|'risky',expectedWorker:'local'|'frontier-session'}>}`. `suiteHash` binds bundled manifest/templates/source/protected checks; `baseSha` pins the actual generated baseline commit. Local task defaults use `review:default`; risky task requires frontier review. No checks-only grant or profile-class permission is created. Root integrates `spillway pilot create DIR`, available without a running service. It prints the manifest and does not enqueue tasks.

`eval/tasks/v1` holds fixed source/check/license assets and task templates for independent greeting/mechanical, slug/small-fix and permission/risky cases. Tasks have disjoint scopes and pinned common baseline; protected checks fail baseline, pass known correct fixture implementations and reject representative broken implementations. Risky work demonstrates holding for an authorized frontier session when availability is off, not a local capability success. Keep this tuning/pilot set separate from held-out evaluations and the seven-case qualification suite. Report all outcomes; do not manufacture accepted/audited results.
