# 0006: Phase 2 reviews, bounded continuation and owner sessions

Accepted 2026-10-12 after the owner merged PR #1 (`1ab2878`) and explicitly authorized Phase 2. This extends the initial Phase 0/1 scope in design §14. The owner selected Claude Code sessions for frontier work and prohibited automatic paid calls.

Use the existing local OpenCode adapter for review in a dedicated detached checkout. A read-only primary agent denies mutation, shell, network and delegation tools; before/after Git checks pin both reviewer checkout and original result. Refuse symlinks and preserve uncertain/mutated evidence. This avoids a second tool loop and keeps independent checks authoritative. Tool policy is defense in depth, not an OS sandbox.

Review reports use strict JSON tied to the latest independently verified SHA. No accepting verdict with blocking findings; stale, duplicate-key, missing, malformed or truncated reports fail closed. Review tier may strengthen but never weaken. A local accepting report is retained when policy now requires frontier review, but cannot authorize readiness. Owner acceptance rechecks current policy, the exact result and required accepting review.

Add explicit pending actions and repair lineage to SQLite v3 instead of interpreting prose reasons. Finalizing evidence/task/action/events is atomic; finalized and uncertain evidence is immutable. One execution slot covers workers, reviewers and owner-session claims. Local continuation is bounded by task attempt limit plus at most one policy-authorized repair; one transport retry per task is free. Repairs retain the original base for cumulative scope/protected checks and archive prior branches without discarding checkout/evidence. Only transport failures may intervene between a repair and its committed parent. A frontier task receives at most one owner-session worker claim; unsuccessful frontier work holds without another loop.

Frontier availability is manually controlled, initially off, with optional exact-instant reset scheduling and private audit events. Availability never initiates a paid provider call. An authenticated, explicitly authorized Claude Code session may claim a frontier worktree or submit a review only for `frontier-ok` repositories. The service performs its own verification and latest-SHA checks; provenance is owner-attested and does not claim cryptographic vendor identity. This respects the owner's account/session workflow and avoids background credentials, subscriptions or spending integration. Automatic limit detection and richer review workflows remain later work.

Interrupted reviewers inherit ADR 0004's global uncertainty fence. Owner reconciliation attests surviving processes were stopped, abandons the task and preserves evidence. No automatic rerun or reuse of uncertain work.

Add reversible per-user launchd/systemd service management with pinned paths, escaped definitions, private logs and a credential-free inherited environment. Explicit owner-only key-file references support authenticated local endpoints without copying keys into service definitions; no account credential discovery. Installation/uninstall touches only known service files and preserves private queue/config/evidence. Fixture tests cover both platforms; live platform checks and clean-machine release onboarding are separate evidence.

Phase 3 scorecards, audits, export, qualification and release remain out of scope. Apache-2.0/DCO, no telemetry, loopback authenticated read-only dashboard, no auto merge/push/deployment, and the non-sandbox trust model remain unchanged.
