# ADR 0015: Use an explicit general worker contract

Accepted 2026-10-13 during the owner-authorized local pilot and qualification work. A fresh pilot achieved valid separate local review; the subsequent complete real v3 workload passed four of seven cases. Observed failures include command wrappers replacing requested direct failure/recovery evidence and partial reads replacing explicitly required full context. Preserve every original outcome.

Set OpenCode's existing primary build agent `prompt` to an exported `WORKER_SYSTEM_PROMPT` in `harness.ts`. This replaces the harness's generic coding instructions while retaining its environment, task, tools, model binding, permissions and one primary inference budget. Use a concise general execution contract: follow the owner's scope and repository conventions, read before editing, execute supplied check commands verbatim with genuine exit status, deliver complete explicitly requested reads, commit the assigned result and report failures truthfully. Legitimate compound commands explicitly supplied by the owner remain valid. Do not encode workload names, paths, expected values or grading predicates.

Keep the reviewer prompt, schemas, protected workload assets, evidence observer, fixed budgets, sampling and model/server settings unchanged. Verify actual installed-binary HTTP requests and tool schemas with a loopback fixture; serialized configuration tests alone are insufficient. Then perform one fresh complete comparison run with the exact same immutable v3 workload. Do not retry indefinitely, combine passing cases, regrade prior outcomes, promote classes or infer owner acceptance. A failed comparison remains a reported failure and an open evidence gate.

Root owns this decision, shared documentation, wire verification and runtime integration. Execution owns only the adapter and its component tests. Independent security review covers the instructions and stopped-service upgrade; clients verify preserved history and final results. Install only a tested committed package with locked dependencies after consistent backup and verified idle/daemon identity. The change introduces no model/tool loop, paid call, schema migration or release authorization.

Observed comparison: five of seven capabilities passed; direct failure/recovery ordering and full-context evidence still failed. All seven commits passed protected checks. Intact todo-write events also fell outside the unchanged closed observer. The general contract remains tested task instructions, not a model-compliance guarantee; no further retry, criterion change or promotion follows.
