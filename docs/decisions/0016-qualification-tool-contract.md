# ADR 0016: Bind qualification to its measured tool contract

Accepted 2026-10-13 after the owner requested PR #10 merge and continued work. The completed v3 comparison contains intact planning-tool events outside its closed observer. Preserve that result and its independent command/full-context failures; changing the observer or filtering historical events would weaken evidence.

Extend internal `HarnessInput.purpose` with `qualification`. Keep the existing build primary, general worker prompt, model, sampling, isolation and inference budget. For this purpose only, use a deny-all permission map allowing the observer's canonical primitives: bash, read, glob, grep, edit, write and apply_patch. OpenCode aliases write/patch permissions to edit and registers model-dependent tools; actual wire verification against the pinned model establishes availability. Ordinary worker/repair and read-only reviewer permissions remain unchanged. Record purpose in new private model metadata, without changing stored historical artifacts or public request/result schemas.

`runQualification` explicitly selects this purpose. Workload revisions, prompts/assets, observer predicates, protected checks, budgets and metadata requirements remain byte-identical. Unknown events still fail the observer. This remains the existing CLI's tool loop, not a command rewrite, answer hint, automatic repair or custom loop.

Verify exact available qualification tools and their unchanged schemas relative to the ordinary-worker subset, selected primary, temperature zero and absence of auxiliary requests with the installed binary. The pinned current model exposes six primitives; patch registration differs for some models, so this is not a universal six-tool assertion. Then run one complete fresh real v3 comparison under the existing local endpoint, with exact source/purpose/tool-contract/prompt/metadata/settings identity recorded privately. Retain every outcome; no automatic repeat or combination of passing cases.

A passed result would establish only the restricted qualification tool configuration. It cannot certify the ordinary worker's extra tool menu, promote classes or justify public reproducibility claims that omit this distinction. Publication remains separately gated. Removing planning tools does not ensure correct direct commands or full reads. Shell execution remains broad; this is not a sandbox.

Root owns contracts, documentation, installed-wire verification, integration and the bounded run. Execution owns adapter/component tests; clients owns runner/component tests. Independent security review covers role isolation and the guarded maintained-service upgrade. No agent commits, paid calls, schema migration, policy grant or release.
